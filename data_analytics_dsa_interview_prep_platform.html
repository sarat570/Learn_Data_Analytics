High-Yield Data Analyst Interview Topics

1. Running Totals & Moving Averages

Always use an unbounded preceding window frame for cumulative sums:
SUM(amount) OVER (PARTITION BY user_id ORDER BY order_date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW).

2. Handling Ties with RANK vs DENSE_RANK

RANK() skips rank positions on ties (1, 2, 2, 4), while DENSE_RANK() keeps rank increments contiguous (1, 2, 2, 3). Essential for "find top N earners without skipping".

3. Day-over-Day & MoM Growth

Use LAG(revenue, 1) OVER (ORDER BY month) to retrieve the previous period value, then compute (rev - prev_rev) * 100.0 / prev_rev.

4. User Retention Rate & Cohorts

Define the cohort baseline using MIN(activity_date) per user, then perform a self-join on subsequent active dates to calculate Day 1, 7, and 30 retention.

Data Analytics DSA Theory Notes

Time & Space Complexities for Analytics

In interview settings, explain how your database would index queries:

  • B-Tree Indexes: $O(\log N)$ for equality and range filters (`BETWEEN`, `>`, `<`).
  • Hash Join vs Merge Join: Hash join is $O(M + N)$ with $O(M)$ memory; Merge join is ideal when both tables are pre-sorted by join key.
  • Window Function Overhead: Usually requires an internal sort $O(N \log N)$ over the partition & order keys.

Data Modeling: Star vs Snowflake Schema

Star Schema: Denormalized dimension tables surrounding a central fact table. Optimized for fast query reads and simpler joins.
Snowflake Schema: Normalized dimensions with hierarchy splits. Saves storage and avoids redundancy at the expense of extra joins.

SQL & Python Quick Cheat Sheet

Common SQL Window Syntaxes
-- Running total
SUM(col) OVER (PARTITION BY group_id ORDER BY date)

-- Relative offsets
LAG(col, 1) OVER (PARTITION BY id ORDER BY date)
LEAD(col, 1) OVER (PARTITION BY id ORDER BY date)

-- Deduplicating top row
WITH ranked AS (
  SELECT *, ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY score DESC) as rn
  FROM submissions
)
SELECT * FROM ranked WHERE rn = 1;
Pandas vs SQL Mappings
-- SQL:
SELECT dept, AVG(salary) FROM emp GROUP BY dept;
# Pandas:
df.groupby('dept')['salary'].mean().reset_index()

-- SQL:
SELECT * FROM orders WHERE amount > 500;
# Pandas:
df[df['amount'] > 500]

Logical SQL Query Execution Order Explainer

Understanding the sequence SQL engines evaluate clauses prevents tricky grouping and alias errors.

1. FROM & JOIN: Tables are gathered, cross-joined, and joined on conditions.
2. WHERE: Filters individual candidate rows before grouping occurs.
3. GROUP BY: Collapses rows sharing identical group keys into single aggregate records.
4. HAVING: Filters aggregated groups using aggregate predicates (`HAVING SUM(amount) > 1000`).
5. SELECT & Window Functions: Expressions, aliases, and window frames are evaluated.
6. DISTINCT, UNION, ORDER BY, LIMIT: Deduplicated, sorted, and row-sliced.
